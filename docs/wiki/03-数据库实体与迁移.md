# 03 — 数据库实体与迁移

## 3.1 数据库概览

| 项 | 值 |
|----|-----|
| ORM | TypeORM 0.3.31 |
| 支持后端 | SQLite（默认）、MySQL 8+、MariaDB 10.6+ |
| Entity 总数 | 31 |
| 迁移数量 | 7（含初始 schema） |
| 同步策略 | `synchronize: false` — **生产绝不自动同步 schema** |
| 迁移运行 | 启动前显式 `node dist/main.js migrate`；Docker 镜像默认 `DB_MIGRATE_ON_START=1` 自动执行 |

### 连接配置（`src/database/data-source-options.ts`）

```
DB_TYPE = sqlite | mysql | mariadb  （默认 sqlite）

SQLite：
  database = DATA_DIR + '/rustdesk-console.db'

MySQL/MariaDB：
  DB_HOST     默认 localhost
  DB_PORT     默认 3306
  DB_USERNAME 默认 root
  DB_PASSWORD 默认 ''
  DB_DATABASE 默认 rustdesk_console
  charset     utf8mb4
```

### 特殊 SQLite 处理

- **写入队列**（[sqlite-write-queue.ts](file:///workspace/src/database/sqlite-write-queue.ts)）：SQLite 单连接下重叠事务会泄漏 SAVEPOINT 导致写入挂起；TypeORM 的 EntityManager 写方法被包装为顺序执行。
- **迁移检查在连接建立后立即执行**：如有 pending migrations 则抛错阻止应用启动（[app.module.ts:75-79](file:///workspace/src/app.module.ts#L75-L79)）。
- **自动 SQLite 唯一索引修复**：`DatabaseInitService` 在启动时确保 `UQ_users_single_owner` 存在。

### MariaDB 特殊处理

- 需要持久化生成列（generated column）来实现默认用户组唯一约束的条件索引，见 `1794700800000-SupportMariaDbDefaultGroupIndex` 迁移。
- 使用独立的 `mysql-dialect.ts` 调整 Dialect 行为。

## 3.2 Entity 清单与分组

全部 Entity 在 [entities.ts](file:///workspace/src/database/entities.ts) 中统一注册到 `DATABASE_ENTITIES` 数组，**运行时与迁移 CLI 共用此数组**，避免两端 schema 漂移。

### 3.2.1 设备与系统（common）

#### Peer（`peers` 表）
**文件**: [peer.entity.ts](file:///workspace/src/common/entities/peer.entity.ts)  
RustDesk 客户端设备主记录。

| 字段 | 类型 | 说明 |
|------|------|------|
| guid | string (PK) | 设备唯一 GUID |
| id | number | 设备 ID（RustDesk 协议内标识） |
| uuid | string | 设备 UUID（客户端硬件指纹） |
| userId | string | 关联的 User GUID（可为空） |
| deviceGroupGuid | string | 设备组 GUID |
| strategyGuid | string | 策略 GUID |
| hostname | string | 主机名 |
| username | string | 登录用户名 |
| os | string | 操作系统 |
| ip | string | 最后上报 IP |
| status | enum PeerStatus | online / offline / disabled |
| **关系** | — | ManyToOne → User / DeviceGroup / Strategy |

特殊处理：`device-identity.util.ts` 的 `isolatedDeviceUuid()` 会为克隆设备生成控制台专用哈希，防止误匹配。

#### Sysinfo（`sysinfos` 表）
**文件**: [sysinfo.entity.ts](file:///workspace/src/common/entities/sysinfo.entity.ts)  
设备系统信息快照（每次 `POST /sysinfo` 追加一条）。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string (PK) | 主键 |
| peerGuid | string | 关联 Peer |
| cpu / memory / disk | string | 硬件信息 |
| createdAt | Date | 上报时间 |

#### DeviceTombstone（`device_tombstones` 表）
**文件**: [device-tombstone.entity.ts](file:///workspace/src/modules/device-group/entities/device-tombstone.entity.ts)  
设备墓碑 —— 克隆隔离机制。当设备因克隆冲突被移除时记录于此。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string (PK) | 主键 |
| deviceUuid | string | 被墓碑化的设备 UUID |
| reason | string | 移除原因 |
| releaseRequested | boolean | 是否已请求解除隔离 |
| idReleased | string | 解除后新分配的设备 ID |

### 3.2.2 用户与身份

#### User（`users` 表）
**文件**: [user.entity.ts](file:///workspace/src/modules/user/entities/user.entity.ts)  
用户主表。

| 字段 | 类型 | 说明 |
|------|------|------|
| guid | string (PK) | 用户 GUID |
| username | string (unique) | 登录用户名 |
| displayName | string | 显示名 |
| email | string (unique) | 邮箱 |
| password | string (select:false) | bcrypt 哈希 |
| note | string | 备注 |
| verifier | string | 验证器 |
| status | int (UserStatus) | -1 未验证 / 0 禁用 / 1 正常 |
| isAdmin | boolean | 是否管理员（条件唯一索引：只有一个 admin） |
| emailVerificationCode | string (select:false) | 邮箱验证码 |
| tfaSecret | string (select:false) | TOTP 密钥 |
| info | text (JSON) | 用户设置 |
| thirdAuthType | string | 第三方认证类型（oidc/ldap） |
| oidcSubject | string (unique) | OIDC subject（`oidc:{provider}:{sub}`） |
| avatar | string | 头像路径 |
| strategyGuid | string | 策略覆盖 |
| userGroupGuid | string | 用户组 |
| **关系** | — | ManyToOne → Strategy / UserGroup；OneToMany → UserToken |

#### UserGroup（`user_groups` 表）
用户组；用作 RBAC 角色分配和地址簿规则的中间层。默认用户组有条件唯一约束（每个数据库只有一个 default 组）。

#### UserToken（`user_tokens` 表）
用户 refresh token / API token。

#### Invitation（`invitations` 表）
邀请注册记录（未验证用户的占位）。

#### LoginSession（`login_sessions` 表）
登录会话；设备、IP、user-agent 审计；支持单设备/多设备策略。

#### PasskeyCredential（`passkey_credentials` 表）
WebAuthn Passkey 凭证（userId + credentialId 唯一）。

#### PasswordResetToken（`password_reset_tokens` 表）
密码重置 token（1790985600002 迁移新增）。

#### OidcProvider / OidcAuthState
- `oidc_providers` — 多 Provider 配置（issuer、clientId、clientSecret）
- `oidc_auth_states` — 授权码流程中间态（state、nonce、pkceChallenge、expiresAt）

## 3.4 迁移历史

迁移全部手写（`typeorm migration:create`），位于 [src/migrations/](file:///workspace/src/migrations/)。

| 时间戳 | 名称 | 作用 |
|--------|------|------|
| `1790985600000` | InitialSchema | 初始 schema，同时提供 SQLite（`initial-schema-sqlite.ts`）和 MySQL（`initial-schema-mysql.ts`）两套建表 SQL |
| `1790985600001` | FixMySqlDefaultUserGroupIndex | MySQL 默认用户组唯一索引修复（旧索引名冲突） |
| `1790985600002` | AddPasswordResetTokens | 新增 `password_reset_tokens` 表（token、userGuid、expiresAt、used） |
| `1791040000000` | AddDeviceTombstones | 新增 `device_tombstones` 表（克隆隔离机制） |
| `1791126400000` | AddDeviceTombstoneReleaseTracking | tombstone 增加 `releaseRequested`、`idReleased` 字段 |
| `1791212800000` | ReplaceNexusWithCustomClientBuilds | 删除旧 `nexus_tokens` / `nexus_builds` 表，新建 `custom_client_builds`（自定义客户端功能替换 Nexus 集成） |
| `1794700800000` | SupportMariaDbDefaultGroupIndex | MariaDB 专用：持久化生成列 + 唯一索引，实现 MySQL 风格的默认用户组条件唯一约束 |

### 运行迁移

```bash
# 生产：在启动迁移
node dist/main.js migrate

# 查看已应用的迁移
node dist/main.js show-migrations

# 对旧 synchronize 数据库做一次性 schema 修复 + baseline 打点
node dist/main.js baseline
```

### 迁移生成

```bash
npx typeorm-ts-node-commonjs migration:generate NewMigrationName -d src/data-source.ts
```

### MariaDB 特殊说明

初始迁移和后续增量迁移对 SQLite/MySQL/MariaDB 有分支逻辑，参见各迁移文件内的 `if (dbType === 'sqlite')` / `if (dbType === 'mysql' || dbType === 'mariadb')`。

## 3.5 DatabaseInitService — 启动初始化

**文件**: [database-init.service.ts](file:///workspace/src/database/database-init.service.ts)

在数据库连接建立、迁移执行完后由 NestJS 生命周期钩子运行：

1. **检查重复 system owner**：`UQ_users_single_owner` 索引，如被破坏则修复。
2. **SQLite 唯一索引修复**：确保索引存在。
3. **创建默认管理员**：
   - 用户名：`databk`
   - 密码：环境变量 `ADMIN_PASSWORD`（未设时跳过创建，避免写入空密码）
   - 如果已有 admin 用户则保留现有凭据。
4. **清理旧 OIDC 数据**：删除无 provider 的 `OidcAuthState` 和孤儿 `OidcProvider`。

## 3.6 Migration Manager — 安全基线

**文件**: [migration-manager.ts](file:///workspace/src/database/migration-manager.ts)

针对从旧版本（使用 `synchronize: true`）升级的数据库：

- `baselineExistingDatabase()` 检测 schema 与当前 entities 的差异，必要时运行一次性 repair SQL 补齐全局索引/列，然后写入 initial migration 的 `*_migrations` 表，使迁移历史与新部署一致。
- `assertNoUndeclaredColumns()` 拒绝 entities 中已不再定义但仍存在于数据库的列，防止 schema repair 误删。
