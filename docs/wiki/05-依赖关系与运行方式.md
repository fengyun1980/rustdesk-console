### 5.1.2 枢纽模块

#### common/*
所有 module 都导入 `common`，提供：
- `Peer` / `Sysinfo` 实体
- `AdminGuard` / `DeviceThrottlerGuard`
- `requestIdMiddleware`
- `data-dir.util`（DATA_DIR / DB_TYPE）

#### settings
**被几乎所有业务模块导入**，通过 `SystemSetting` 表提供：
- SMTP 配置（email 用）
- 站点 URL（user 邀请用）
- 审计保留天数（audit-cleanup 用）
- LDAP / OIDC / Web Client / Custom Client 配置

#### user-group
几乎所有业务模块都依赖用户组：
- `auth`：登录时查询用户组（RBAC 授权）
- `rbac`：用户组级角色分配
- `address-book`：地址簿访问规则按用户组粒度
- `strategy`：策略可分配给用户组
- `sysinfo` / `heartbeat` / `user` / `ldap` / `oidc` / `email` 等

### 5.1.3 反向依赖图

```
被最多模块导入 → 被较少模块导入 ↓

settings ◄── email, auth, user, audit, ldap, oidc, sysinfo, heartbeat,
             server-management, web-client, custom-client, rbac...

user-group ◄── auth, user, address-book, strategy, rbac, sysinfo,
               heartbeat, ldap, oidc, device-group...

rbac ◄── auth, user, audit, address-book, device-group,
         strategy, custom-client, server-management, web-client...

auth ◄── oidc, user （纯出方向）

heartbeat ◄── device-group （心跳数据被设备列表消费）

strategy ◄── heartbeat, device-group （被消费，无下游模块）

address-book ◄── sysinfo, dashboard （设备自动加入 + 统计）

audit ◄── dashboard （连接/文件/告警审计被仪表盘统计）

updater ◄── system-update（通过 Unix Socket）
          ← 无反向依赖，updater 完全独立
```

## 5.3 运行方式

### 5.3.1 环境变量

全部环境变量模板在 `.env.example`，按领域分组：

| 组 | 变量 | 默认 | 说明 |
|----|------|------|------|
| 基础 | `PORT` | 3000 | API 端口 |
| | `HOST` | — | 绑定地址（未设则 0.0.0.0） |
| | `LOG_LEVEL` | log | verbose / debug / log / warn / error / fatal |
| | `JWT_SECRET` | — | **必填**，JWT 签名密钥 |
| | `DATA_DIR` | ./data | 数据目录（SQLite + 业务文件） |
| 数据库 | `DB_TYPE` | sqlite | sqlite / mysql / mariadb |
| | `DB_HOST` / `DB_PORT` / `DB_USERNAME` / `DB_PASSWORD` / `DB_DATABASE` | — | MySQL 配置 |
| 迁移 | `DB_MIGRATE_ON_START` | 1 | Docker 镜像启动时是否自动迁移 |
| 管理员 | `ADMIN_PASSWORD` | — | 首次启动时创建 admin 用户 |
| 更新器 | `SYSTEM_UPDATE_INSTALLATION` | — | installation.json 路径 |
| | `SYSTEM_UPDATE_SOCKET` | — | IPC Unix Socket 路径 |
| | `SYSTEM_UPDATE_MAINTENANCE_FILE` | — | 维护栅栏文件 |
| | `SYSTEM_UPDATE_COMPOSE_ROOT` | — | docker-compose.yml 目录 |
| | `SYSTEM_UPDATE_SOCKET_GID` | 1000 | socket 组权限 |
| | `SYSTEM_UPDATE_MYSQL_EXCLUSIVE_SCHEMA` | false | MySQL 备份恢复安全前提 |
| Docker Compose | `CONSOLE_INSTALL_DIR` | — | **必填**，compose 项目根绝对路径 |
| | `COMPOSE_PROFILES` | — | 可选：`server` 同时启 hbbs/hbbr |
| | `RUSTDESK_RELAY_ADDRESS` | — | server profile 用 |
| | `SERVER_MANAGEMENT_TOKEN` | — | server profile 用（≥ 32 字符） |

### 5.3.2 方式一：Docker Compose（推荐生产）

```bash
# 1. 下载 compose 文件
cp docker-compose.yml docker-compose.override.yml .env.example ./deploy-dir/
cd ./deploy-dir

# 2. 编辑环境变量
cp .env.example .env
chmod 600 .env
# ★ 必填: JWT_SECRET, ADMIN_PASSWORD, CONSOLE_INSTALL_DIR
#   CONSOLE_INSTALL_DIR = pwd 输出的绝对路径

# 3. 启动
docker compose up -d
# 前端 http://localhost:21114
# 后端 http://localhost:3000/api （私有网络，不对外）
```

**compose 服务清单**：

| 服务 | 镜像 | 说明 |
|------|------|------|
| `rustdesk-console` | `databk/rustdesk-console:latest` | 后端 API（UID/GID 1000） |
| `rustdesk-console-web` | `databk/rustdesk-console-web:latest` | 前端（nginx，端口 21114） |
| `updater` | `databk/rustdesk-console:latest` | 系统更新控制面（同镜像，不同 command） |
| `hbbs` / `hbbr` | `databk/rustdesk-server:latest` | 可选 RustDesk Server（profile: server） |

镜像同步发布到 Docker Hub 和 GHCR（`ghcr.io/databk/rustdesk-console`）。

**维护流程**：从前端"Update System"发起更新 → updater IPC 控制面执行 → 备份 → 切换镜像 → 健康检查 → 完成。

### 5.3.3 方式二：Docker CLI（手动更新）

```bash
docker network create rustdesk-net

docker run -d \
  --name rustdesk-console \
  --network rustdesk-net \
  -e JWT_SECRET=your-super-secret-key \
  -e ADMIN_PASSWORD=your-admin-password \
  -v ./data:/data \
  -p 3000:3000 \
  databk/rustdesk-console:latest

docker run -d \
  --name rustdesk-console-web \
  --network rustdesk-net \
  -p 21114:80 \
  -e BACKEND_URL=http://rustdesk-console:3000 \
  databk/rustdesk-console-web:latest
```

**注**：不包含 updater，更新需手动拉取新镜像重建。

### 5.3.4 方式三：SEA 预编译单可执行文件

```bash
# 从 Releases 页面下载（匹配平台+架构+libc）
# Linux x64 musl:   rustdesk-console-linux-x64-musl.tar.gz
# Linux x64 glibc:  rustdesk-console-linux-x64-glibc.tar.gz
# Linux arm64:      rustdesk-console-linux-arm64.tar.gz
# Windows x64:      rustdesk-console-windows-x64.zip
# macOS x64:         rustdesk-console-darwin-x64.tar.gz
# macOS arm64:       rustdesk-console-darwin-arm64.tar.gz

tar xzf rustdesk-console-linux-x64-musl.tar.gz
cd rustdesk-console

# 初始化
./rustdesk-console migrate

# 生产启动
PORT=3000 \
JWT_SECRET=your-secret \
ADMIN_PASSWORD=your-password \
DATA_DIR=./data \
./rustdesk-console
```

**Linux systemd 安装脚本**（带 updater 自动更新）：

```bash
sudo ./deployment/install-linux.sh
# 自动：安装后端 + 前端 nginx + systemd unit + updater
# 初始凭据保存在 /etc/rustdesk-console/backend.env
```

### 5.3.5 方式四：源码构建

```bash
# 要求 Node.js >= 20.0.0, npm >= 9.0.0
git clone https://github.com/databk/rustdesk-console.git
cd rustdesk-console
npm install

cp .env.example .env
# 编辑 .env（至少 JWT_SECRET、ADMIN_PASSWORD）

# 开发模式（热重载）
npm run start:dev

# 构建
npm run build

# 生产运行
node dist/main.js migrate      # 首次或升级时
npm run start:prod             # 或 node dist/main.js
```

### 5.3.6 方式五：OpenWrt 原生包

```bash
# 在 OpenWrt 25.12+ SDK 中构建
cd openwrt
# 构建 rustdesk-console 后端 + luci-app-rustdesk-console LuCI 前端
# 具体步骤见 openwrt/README.md

# 安装
opkg install rustdesk-console_*.ipk
opkg install luci-app-rustdesk-console_*.ipk

# 启用
/etc/init.d/rustdesk-console enable
/etc/init.d/rustdesk-console start
```

### 5.3.7 SEA 构建（源码生成 SEA 包）

```bash
# 源码仓库内构建
npm run build:sea            # 生成 dist/sea/rustdesk-console + assets
npm run build:openwrt        # SEA + OpenWrt runtime bundle
```

构建脚本（`scripts/build-sea.mjs`）做：TS 编译 → esbuild 打包 → 生成 SEA blob → 复制 Node binary → 组装发布目录。

## 5.4 API 端点概览

所有 REST 路由统一前缀 `/api`，由 `application.ts` 设置：

```
/api
├── auth/                认证：login, logout, refresh, current, login-options, totp, passkey
├── password-reset/      密码重置
├── user/                用户自管理：GET/PUT /user, verify-email, avatar
├── admin/user/          管理员用户管理：列表、邀请、禁用
├── oidc/                OIDC 授权码流程
├── settings/            系统设置
├── ldap/                LDAP 配置
├── permissions/          RBAC 权限目录
├── roles/               RBAC 角色管理
├── user-role/           用户-角色分配
├── heartbeat/           设备心跳（客户端 POST）
├── sysinfo/             系统信息上报
├── devices/             设备列表、断开
├── device-groups/       设备组 CRUD
├── strategy/            策略 CRUD
├── address-book/        地址簿、标签、规则
├── audit/               连接/文件/告警审计（客户端 POST，管理员查询）
├── dashboard/           概览统计、趋势
├── server-management/   RustDesk hbbs/hbbr 管理
├── web-client/          Web Client 网关管理（WebSocket Gateway 在 /api/web-client/socket）
├── custom-client/       自定义客户端构建管理
├── update-check/        管理员更新检查
├── system-update/       管理员系统更新：capabilities, plans, jobs

├── login-options        # 登录选项（公开：有哪些 auth 方式）
└── public/config        # 前端公共设置（公开）
```

## 5.5 全局 Guard 链

```
请求进入 →
  1. DeviceThrottlerGuard        全局限流，优先按 body.id/uuid/deviceId
  2. JwtAuthGuard                检查 JWT；@Public() 装饰的路由跳过
  3. RbacGuard                   读取 @RequirePermission metadata；超级管理员直接放行
  → 到达 Controller Handler
```

## 5.6 Cron 定时任务

| 任务 | 模块 | 频率 | 作用 |
|------|------|------|------|
| 审计日志清理 | audit-cleanup | `0 0 * * *`（每日午夜） | 按 `auditRetentionDays` 删除 4 类审计表过期记录 |
| Refresh Token 清理 | token-cleanup | 定期 | 删除过期 refresh token |
| OIDC AuthState 清理 | oidc-auth-state-cleanup | 定期 | 删除过期授权状态 |
| Update Check | update-check | 定期 Cron | 查询官方 release catalog 缓存 |
| Updater Reconcile | updater (mode=updater) | 每 10s | 检测 worker 崩溃并重启 |
