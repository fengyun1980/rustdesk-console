# RustDesk Console — Code Wiki

> RustDesk Console 是 RustDesk 远程桌面生态的企业级管理平台，开源自托管替代 RustDesk Server Pro。
> 技术栈：**NestJS 11 + TypeScript + TypeORM 0.3 + SQLite/MySQL/MariaDB + JWT + Passport**。

---

## 1. 项目定位

| 维度 | 说明 |
|------|------|
| 名称 | `rustdesk-console` |
| 版本 | 1.11.0 |
| 许可证 | AGPL-3.0 |
| Node.js | ≥ 20.0.0 |
| 架构风格 | NestJS 模块化单体（Modular Monolith） |
| 对外接口 | REST API（`/api` 前缀）+ WebSocket（Web Client 通道）+ IPC Socket（Updater 控制面） |
| 数据库 | 默认 SQLite；可选 MySQL 8+ 或 MariaDB 10.6+ |
| 运行形态 | Docker Compose / 预编译 SEA 单可执行文件 / 源码构建 / OpenWrt 原生包 |

前端是独立仓库 [rustdesk-console-web](https://github.com/databk/rustdesk-console-web)，后端通过 HTTP/JSON 和 WebSocket 对外服务。

## 3. 启动流程

`src/main.ts` 是真正的入口，它按 **最早匹配优先** 的顺序分派执行模式：

```
node dist/main.js [args...]
│
├── --system-update-mode=<updater|worker|recover>
│       → updater/entrypoint.ts :: updaterMain(mode)
│         （不加载 TypeORM，直连 IPC / 文件系统）
│
├── "self-test"
│       → common/utils/native-self-test.ts :: testNativeModules()
│
├── "migrate" | "baseline" | "show-migrations"
│       → database/migration-command.ts :: runMigrationCommand()
│
└── 默认（无参数）
        → application.ts :: bootstrap()
```

### bootstrap() 内部管线（`src/application.ts`）

| 步骤 | 作用 |
|------|------|
| `waitForApplicationStart()` | 等待 updater 的启动同步信号（维护模式 fence） |
| `NestFactory.create(AppModule, { logger })` | 构造 NestJS 容器 |
| `app.enableShutdownHooks()` | 优雅关闭 |
| `requestIdMiddleware` | 为每个请求分配 `X-Request-Id`，绑定 AsyncLocalStorage |
| `rbacRequestScopeMiddleware` | 请求级 RBAC 缓存绑定（一次查询，全程复用） |
| 维护模式拦截 | 非 `/api/system-update/*` 请求在系统更新期间返回 503 |
| `cookieParser()` | Cookie 解析（JWT 双策略：Header + Cookie） |
| `setGlobalPrefix('api')` | 所有路由挂在 `/api` 下 |
| `enableCors` | `origin:true` + `credentials:true` |
| `GlobalPipes ValidationPipe` | whitelist + transform + forbidNonWhitelisted |
| `app.listen(PORT, HOST)` | 默认 3000 |

### AppModule 全局注册

```ts
providers: [
  { provide: APP_GUARD, useClass: DeviceThrottlerGuard },   // 全局限流（按设备 ID）
  { provide: APP_GUARD, useClass: JwtAuthGuard },           // JWT 认证（@Public 豁免）
  { provide: APP_GUARD, useClass: RbacGuard },              // RBAC 鉴权
  { provide: APP_INTERCEPTOR, useClass: ConsoleAuditInterceptor }, // 控制台操作审计
]
```

TypeORM 的 `dataSourceFactory` 会在连接建立后 **立即检查是否有 pending migrations**，有则抛错阻止启动，避免 schema 漂移。

## 4. 模块总览

应用被划分为 **21 个 feature module + common + database + updater**，分层关系如下：

```
                 ┌──────────────────────┐
                 │      AppModule       │
                 │ （全局 Guard/拦截器） │
                 └──────────┬───────────┘
                            │ import
        ┌───────────────────┼───────────────────┐
        │                   │                   │
┌───────▼──────┐    ┌───────▼──────┐    ┌──────▼─────┐
│ common/      │    │ database/    │    │ updater/   │
│ guards/      │    │ TypeORM 连接 │    │ IPC 控制面 │
│ middleware   │    │ 初始化/迁移   │    │ Planner    │
│ entities     │    │ SQLite 队列  │    │ Worker     │
│ utils        │    │              │    │ Backups    │
└───────┬──────┘    └───────┬──────┘    └────────────┘
        │                   │
        └─────────┬─────────┘
                  ▼
     ┌────────────┼──────────────────────────────────────────┐
     │ 认证/身份   │                    业务核心                │
     ├────────────┼──────────────────────────────────────────┤
     │ auth       │  heartbeat      address-book            │
     │ rbac       │  device-group   strategy                │
     │ oidc       │  user           user-group              │
     │ ldap       │  sysinfo        dashboard               │
     ├────────────┼──────────────────────────────────────────┤
     │ 设置/辅助   │                    平台运维                │
     ├────────────┼──────────────────────────────────────────┤
     │ settings   │  audit          system-update            │
     │ email      │  update-check   server-management        │
     │ custom-cli │  web-client                                │
     └────────────┴──────────────────────────────────────────┘
```

### 依赖方向原则

- `common/*` 和 `database/*` 是底层，**不** import modules 目录。
- feature modules 之间 **可相互 import**，但实际依赖遵循：`auth → user-group/settings/rbac`、`user → auth/email/settings`、`audit → settings/rbac` 等。
- `updater/*` 是 **独立子系统**，有自己的进程模型、IPC 协议和状态存储，**不**与 NestJS 容器交互；由 `system-update` 模块通过 Unix Socket 调用其控制面。

## 6. 运行方式速查

| 方式 | 命令 |
|------|------|
| 开发热重载 | `npm run start:dev` |
| 源码生产构建 | `npm run build && node dist/main.js migrate && npm run start:prod` |
| Docker Compose | `docker compose up -d`（前端 :21114，后端 :3000） |
| SEA 单可执行文件 | `./rustdesk-console migrate && ./rustdesk-console` |
| 迁移管理 | `npm run db:migrate` / `npm run db:show` |
| 迁移生成 | `npm run migration:generate -- -d src/data-source.ts` |
| 测试 | `npm test`（Jest，匹配 `**/*.spec.ts`） |
| 格式化 | `npm run format` / `npm run lint` |

详细运行参数、环境变量和 OpenWrt 打包见后续 Wiki 文档与项目根目录 README。
